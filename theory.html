Hold this picture: the browser never runs Java servlet code. Tomcat runs it. The student only sees HTML.
  1. The student opens a URL such as /basic-servlets/httpmethods.
  2. Tomcat reads web.xml and finds the Java class for that path.
  3. The container calls doGet or doPost (or PUT/DELETE if the lab button sends them).
  4. Your method writes HTML. The browser paints that page. That is the program output.

B) Visual cards — every syllabus idea

1. Servlet — what / why / how

Static HTML→Servlet + if/else→Page per user

Need: a live site must change after a form. Working: request in, HTML out.

2. HTTP methods

GET readPOST savePUT updateDELETE remove

Hospital-counter verbs. OPTIONS = menu of methods. TRACE = echo (often blocked).

3. GET vs POST

GET → address bar≠POST → body

Search may use GET. Login password must use POST.

4. Lifecycle

init 1×→service N×→destroy 1×

Like a restaurant kitchen: open once, cook many orders, close at shutdown.

5. Config vs Context

Config = this servlet≠Context = whole app

Init-param is one shop. Context-param is the mall name for everyone.

6. Forward vs Redirect

Forward same request≠Redirect new URL

Waiter to kitchen vs food-app → UPI. Address bar tells you which.

7. Cookie

Server Set-Cookie→Browser store→Sent again

Remember-me in the browser. Not for passwords. Delete with maxAge 0.

8. HttpSession

Login→setAttribute→Welcome→invalidate

Gmail-style login. Data lives on the server. Cookie only carries the session id.

9. URL rewriting

Cookies off→jsessionid in link

When the browser will not store a cookie, the id travels in the URL.

10. Hidden field

Not in address barbutvisible in View Source

Multi-step exam form. Next POST carries the name. Not a secret.

11. Capstone portal

POSTSessionCookieForwardLogout

Join the unit: login java / servlet. Wrong password includes the form again.

C) Two comparisons you must not mix

GET — search / view

Data rides in the URL: /search?roll=101. Bookmarkable. Do not put a password here. Real life: Google / PNR search.

POST — submit / save

Data rides in the body. Address bar stays /register. Real life: Gmail login, checkout.

Cookie — browser

Small name=value on the client. Comes back on later requests. “Remember my name.”

HttpSession — server

Map on Tomcat, keyed by session id. “You are logged in as java.” Logout = invalidate().

Forward — same request

Server hands the work to another servlet. Address bar does not change. Waiter to kitchen.

Redirect — new request

Browser is told to open another URL (302). Address bar changes. Food app → UPI / “go to login”.
