What this project does

ShopEasy is a tiny shop. You track an order, place an order, change the city, or cancel. Search uses GET (data in the URL). Checkout and a product review use POST (data not in the URL).

  1. Place order Rahul / 101 / Solapur (POST). Address bar stays /httpmethods.
  2. Track order 101 (GET). Address bar shows ?roll=101.
  3. Change city to Pune (PUT). Cancel order 101 (DELETE). Track again — not found.
  4. On this same page: search product Java (GET) then post a review (POST).

2) Place a new order (POST)

Like Amazon Checkout. Name and city stay out of the URL.

3) Change delivery city (PUT)

Like Edit address. Place the order first.

4) Cancel the order (DELETE)

Like Cancel order. Then Track must not find it.

5) What can this window do? (OPTIONS)

Like asking Amazon “what actions are allowed?”. A form cannot send OPTIONS, so this button uses fetch.

6) Debug echo (TRACE)

Only for debug. Tomcat 11 may block it. That is normal. Write “TRACE blocked” in the journal if it fails.

7) Search a product (GET) vs write a review (POST)

Same ShopEasy page. Second Java class: GetPostDiffServlet.

GET = search. Address bar will show ?q=Java.
