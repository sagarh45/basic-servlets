Small project: MyMail account

One HTML page. Two ways to remember a user: a cookie in the browser and an HttpSession on the server. Then one portal that uses both. Login is always java / servlet. A password is never stored in a cookie.

What this project does

HTTP forgets you after every click. MyMail remembers you in two places, and you can see the difference.

  1. Cookie — the browser keeps user=Rahul. Home greets you without asking again. Forget me deletes it with setMaxAge(0).
  2. HttpSession — the name lives in Tomcat memory. Welcome reads getSession(false). Logout calls invalidate().
  3. Full portal — correct login: session + cookie + forward, so the URL stays /CapstoneLogin. Wrong password: include shows the form again. Logout clears both.

A) Remember me on this browser (cookie)

Like YouTube “Continue as Rahul”. Four Java classes: Cookie1 writes, Cookie2 reads on Home, Cookie3 lists, CookieDelete deletes. Write first, then Read — a cookie you just wrote is not in the same request.

2. Read on Home  |  List cookies  |  3. Forget me (delete)

Many names at once? Open the cookie write / read / delete page.

B) Sign in (HttpSession)

Like Gmail. The name is stored on the server, not in the browser. Three Java classes: NotesSessionLogin, NotesSessionWelcome, NotesSessionLogout. Try a wrong password too, then Logout and open Welcome again.

Open Welcome  |  Logout (invalidate)

C) Full MyMail portal (cookie + session together)

Joins both tools. Correct login stores the name in the session, sets a 7-day remember cookie (name only), and forwards to Welcome, so the URL stays /CapstoneLogin. Wrong password includes this form again. Logout invalidates the session and deletes the cookie.

Open Welcome  |  Logout (clear both)
