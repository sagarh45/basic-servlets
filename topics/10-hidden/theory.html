10. Session Management - Hidden Form Field

Theory Lab Setup Index
Verified for Apache Tomcat 11.0.24 (Jakarta EE 11 / Servlet 6.1) + JDK 21+
Every program uses jakarta.servlet.* only. See Lab Setup.

This page is theory only: meaning, real-life examples, diagrams, functions (syntax + use + example) and complete code. Copy the journal problem statement from the ICA Practicals tab or from the program Source page.

A) Concept in simple English

A two-page Amazon / IRCTC form asks name on page 1 and seats on page 2. The name is posted again as <input type="hidden"> so the server still has it. It is not in the address bar, but View Source shows it — so it is not a secret (unlike HttpSession). Login: java / servlet. Hidden field: session_id=054.

A hidden form field is <input type="hidden">. The user does not see it, but it is submitted with the form.

This lab sends session_id=054 with login and password. On success Valid forwards to Welcome. Welcome still sees the same request parameters (including the hidden field).

Hidden fields are not secret. Anyone can View Source.

Picture it from daily life

One-line rule: A hidden field is a line folded inside a booking form. You do not see it on screen, but View Source shows it. It is not a secret and not a server session.

The story (two-page IRCTC / Amazon checkout)

Page 1 asks name. Page 2 asks seats. The site must not make you type the booking id again. The HTML of page 2 includes:

<input type="hidden" name="session_id" value="054">

When you click Submit, login, password and that hidden id travel together (this lab uses POST). Valid checks java / servlet. On success it forwards to Welcome on the same request, so Welcome can still read session_id with getParameter.

A friend who right-clicks View Source can still read 054. So: hidden ≠ encrypted. Passwords belong in POST + HttpSession, not in a hidden field.

What you will see

Welcome prints the user and session_id=054. The address bar does not show the hidden value (POST). View Source of the form still does.

Easy mistake

Writing “hidden field is secure like HttpSession.” Session data lives on the server. Hidden data lives in HTML anyone can open.

Real-life examples (short recap)

Two-page IRCTC / Amazon checkout

Page 1: name. Page 2: seats. Hidden fields carry the booking id so you do not type it again. A friend who Views Source can still see it.

CSRF token on a real site

Production sites hide a random token in the form. Same HTML trick; still not encryption.

Why not for a password

Password in a hidden field is visible in View Source. Use HttpSession after POST login.

F) Complete HTML + Java + XML — every line explained

<form method="post" action="Valid">                 <!-- POST so password is not in the URL -->
  Login: <input name="login" value="java">         <!-- Visible field -->
  Password: <input name="pwd" type="password" value="servlet">
  <input type="hidden" name="session_id" value="054"> <!-- Not on screen; still submitted -->
  <input type="submit" value="Execute">
</form>
import java.io.*;
import jakarta.servlet.*;
import jakarta.servlet.http.*;

public class Valid extends HttpServlet {
    public void doPost(HttpServletRequest request, HttpServletResponse response)
            throws ServletException, IOException {
        response.setContentType("text/html");
        PrintWriter out = response.getWriter();
        String login = request.getParameter("login");       // Visible field
        String pwd = request.getParameter("pwd");           // Password (body)
        if (login != null && pwd != null
                && login.equals("java") && pwd.equals("servlet")) {
            RequestDispatcher rd = request.getRequestDispatcher("Welcome");
            rd.forward(request, response);                  // Same request → Welcome sees hidden field
        } else {
            out.println("<h1>Incorrect LoginId/Password</h1>");
            request.getRequestDispatcher("/hidden_login.html").include(request, response); // Form again
        }
    }
}
public class Welcome extends HttpServlet {
    public void doPost(HttpServletRequest request, HttpServletResponse response)
            throws ServletException, IOException {          // Forward keeps POST
        response.setContentType("text/html");
        PrintWriter out = response.getWriter();
        out.println("<h1>id:" + request.getParameter("session_id") + "</h1>"); // Hidden field
        out.println("<h3>Welcome " + request.getParameter("login") + "</h3>");
        out.println("<p><a href='hidden_login.html'>Back</a></p>");
    }
}
