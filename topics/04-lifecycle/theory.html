4. Servlet Lifecycle

Theory Lab Setup Index
Verified for Apache Tomcat 11.0.24 (Jakarta EE 11 / Servlet 6.1) + JDK 21+
Every program uses jakarta.servlet.* only. See Lab Setup.

This page is theory only: meaning, real-life examples, diagrams, functions (syntax + use + example) and complete code. Copy the journal problem statement from the ICA Practicals tab or from the program Source page.

A) Concept in simple English

A restaurant kitchen opens once in the morning, cooks hundreds of orders during the day, and closes at night. It does not rebuild the kitchen for every plate. A servlet is the same: Tomcat constructs the object, calls init once, then reuses that object. Counters on the result page prove that init ran once and service ran many times.

Tomcat 11 owns the servlet lifecycle. You override methods; the container calls them.

load → init() once → service() / doGet() for every request → destroy() once when undeployed.

This lab uses <load-on-startup>1</load-on-startup> so init can run when the app starts, not only on the first hit.

Picture it from daily life

One-line rule: Tomcat opens the kitchen once (init), cooks many orders (service / doGet), and closes once (destroy). It does not rebuild the kitchen for every plate.

The story (restaurant kitchen)

  1. Morning — open (init) — Lights on, gas on, counters set to zero. This happens once when Tomcat loads the servlet (this lab uses load-on-startup so it can happen at deploy, not only on the first click).
  2. Day — each order (service then doGet) — Table 1 refreshes. Table 2 refreshes. Each refresh is a new request. The same kitchen object serves them. The “orders cooked today” number goes 1, 2, 3… That growing number is your proof.
  3. Night — close (destroy) — You stop Tomcat or undeploy the app. The kitchen closes once. Watch the Tomcat console for the destroy message. The browser page will not show destroy, because the kitchen is already closed.

You never shout “open the kitchen!” from inside one order. You do not write new LifecycleServlet(). Tomcat owns the keys.

Story → Java (same idea)

RestaurantServlet method
Open once, set up the stoveinit(ServletConfig) — call super.init(config)
Every order at the counterservice (count) then doGet (print the page)
Close the kitchendestroy() — close files / log a line
Do not rebuild the kitchen per plateDo not call init from doGet

What you will see

Refresh five times. init count stays 1 (or a small number). service / request count climbs. That difference is the viva answer.

Easy mistake

Thinking a new servlet object is created on every refresh. If that were true, init would increase every time. It does not.

Real-life examples (short recap)

Restaurant kitchen hours

init = lighting the stove (once). service/doGet = each plate. destroy = switching off when Tomcat stops. You would never rebuild the kitchen for every plate — that is why init count stays small.

ATM / cinema box office

The machine starts once. Each customer is a request. Shutdown is destroy.

What not to do

Do not call init() or destroy() from doGet. Do not write new LifecycleServlet() yourself. Tomcat owns the lifecycle.

D) Full syntax

@Override
public void init(ServletConfig config) throws ServletException {
  super.init(config);
  initCount++;
}

@Override
protected void service(HttpServletRequest request, HttpServletResponse response)
    throws ServletException, IOException {
  serviceCount++;
  super.service(request, response);  // then doGet/doPost
}

@Override
protected void doGet(HttpServletRequest request, HttpServletResponse response)
    throws ServletException, IOException {
  response.setContentType("text/html");
  PrintWriter out = response.getWriter();
  out.println("init count = " + initCount);
  out.println("service count = " + serviceCount);
}

@Override
public void destroy() {
  destroyCount++;
  super.destroy();
}
Code / LineSimple meaning
super.init(config)Stores ServletConfig. Required if you override init(ServletConfig).
super.service(...)Lets HttpServlet call doGet or doPost.
initCount vs serviceCountinit stays 1; service grows. That is the lab proof.
destroy()You will not see it in the browser. See Tomcat console.

E) Functions — syntax, use and example

Each function below is the Java for the daily-life story above. Read the meaning, then the syntax, then the lab row.

Tomcat owns the life of the servlet object. You override methods. You do not call them from main().

1. Function: init

Simple meaning: Runs once when Tomcat loads this servlet. Open the office. Read init-param here if you wish.

Full syntax:

@Override
public void init(ServletConfig config) throws ServletException {
    super.init(config);
    initCount++;
}
ItemSimple English
Parametersconfig — this servlet’s ServletConfig
Returnsvoid
When to use (USE)Start counters, open a file, read init-param. Always call super.init(config).
Lab exampleLifecycleServlet: initCount becomes 1. Refresh does not add another init.
Common mistakeSkipping super.init(config) — getServletConfig() may fail later.

2. Function: service

Simple meaning: Runs on every HTTP request, then Tomcat still calls doGet or doPost if you call super.service.

Full syntax:

@Override
protected void service(HttpServletRequest request, HttpServletResponse response)
        throws ServletException, IOException {
    serviceCount++;
    super.service(request, response);
}
ItemSimple English
Parametersrequest, response
Returnsvoid
When to use (USE)Count visits, log the method, then dispatch.
Lab exampleEach refresh: serviceCount grows 1, 2, 3…
Common mistakeForgetting super.service — doGet never runs, page stays blank.

3. Function: doGet / doPost

Simple meaning: Write the HTML the student sees. Runs after service on each matching request.

Full syntax:

protected void doGet(...) throws ServletException, IOException
ItemSimple English
Parametersrequest, response
Returnsvoid
When to use (USE)Print counters and the last visitor name.
Lab exampleGET opens the book. POST signs a name then the same HTML is shown.
Common mistakePutting init() logic inside doGet — init would then run every refresh.

4. Function: destroy

Simple meaning: Runs once when the app is undeployed or Tomcat stops. Lock the office.

Full syntax:

@Override
public void destroy() {
    System.out.println("[LifecycleServlet] destroy");
}
ItemSimple English
Parametersnone
Returnsvoid
When to use (USE)Close files / database. Message is on the Tomcat console, not in the browser.
Lab exampleStop the app in Tomcat Manager — console prints destroy.
Common mistakeWaiting to see destroy() in the web page. It will never appear there.

F) Complete Java program — every line explained

import java.io.IOException;
import java.io.PrintWriter;
import jakarta.servlet.ServletConfig;            // Passed to init(); holds init-param
import jakarta.servlet.ServletException;
import jakarta.servlet.http.HttpServlet;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;

public class LifecycleServlet extends HttpServlet {

    static int initCount = 0;        // How many times init ran (expect 1 per load)
    static int serviceCount = 0;     // How many HTTP requests were served
    static String lastVisitor = "-"; // Optional: last POST visitor name

    @Override
    public void init(ServletConfig config) throws ServletException {
        super.init(config);          // MUST store config; otherwise getServletConfig() fails
        initCount++;                 // Proof: this block is not per-refresh
        System.out.println("init count=" + initCount); // Tomcat console
    }

    @Override
    protected void service(HttpServletRequest request, HttpServletResponse response)
            throws ServletException, IOException {
        serviceCount++;              // Every GET/POST hits service first
        super.service(request, response); // Dispatch to doGet or doPost
    }

    @Override
    protected void doGet(HttpServletRequest request, HttpServletResponse response)
            throws ServletException, IOException {
        show(response, "GET view book");  // Browser refresh uses GET
    }

    @Override
    protected void doPost(HttpServletRequest request, HttpServletResponse response)
            throws ServletException, IOException {
        lastVisitor = request.getParameter("visitor"); // Form field from Execute page
        show(response, "POST signed " + lastVisitor);
    }

    @Override
    public void destroy() {
        System.out.println("destroy"); // Visible only in Tomcat log when app stops
        super.destroy();
    }

    private void show(HttpServletResponse response, String msg) throws IOException {
        response.setContentType("text/html");
        PrintWriter out = response.getWriter();
        out.println("<h2>" + msg + "</h2>");
        out.println("<p>init=" + initCount + " service=" + serviceCount
                + " lastVisitor=" + lastVisitor + "</p>");  // Journal proof
        out.println("<p><a href='lifecycle.html'>Back</a></p>");
    }
}
