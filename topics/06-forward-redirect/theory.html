6. Forwarding and Redirection of Requests

Theory Lab Setup Index
Verified for Apache Tomcat 11.0.24 (Jakarta EE 11 / Servlet 6.1) + JDK 21+
Every program uses jakarta.servlet.* only. See Lab Setup.

This page is theory only: meaning, real-life examples, diagrams, functions (syntax + use + example) and complete code. Copy the journal problem statement from the ICA Practicals tab or from the program Source page.

A) Concept in simple English

You sit at a restaurant table. The waiter carries your order slip to the kitchen inside the same restaurant. You never stand up. The table number does not change. That is forward.

A food-delivery app then says “Pay with UPI” and opens PhonePe / Google Pay. You leave the restaurant screen. The address bar becomes the UPI page. That is redirect.

Both lab paths still land on TargetServlet. Look at the address bar and at request attributes — that is how you prove which path ran.

forward is a server-side hand-off of the same request. The browser address bar stays /forward. Request attributes set by ForwardServlet are still visible in TargetServlet.

sendRedirect tells the browser to make a new request. Tomcat sends HTTP 302 + Location. The address bar changes to /target. Request attributes from the first servlet are lost.

include inserts another resource into the same response (same request). Wrong PIN on a payment screen: show the error and the same form again.

Picture it from daily life

One-line rule: Forward = waiter takes the slip to the kitchen; you stay at the same table (URL does not change). Redirect = the app sends you to PhonePe; you leave and the address changes. Include = wrong PIN: the same payment screen comes back with an error.

The story (restaurant + UPI)

1. Forward — kitchen in the same restaurant

You order at Table 7. The waiter does not send you to another shop. She walks your slip to the kitchen. You still sit at Table 7. The kitchen writes “ready” on the same slip (request attributes still there).

In the lab: browser calls /forward. ForwardServlet puts message and source in the request bag and calls forward to TargetServlet. The page you see is written by Target, but the address bar still shows /forward.

2. Redirect — pay in another app

Swiggy / Zomato is not a bank. It sends you to UPI. You leave the food app. PhonePe starts a new conversation. Notes written on the restaurant slip are not inside PhonePe.

In the lab: /redirect sends HTTP 302 + Location. The browser itself requests /target. Address bar changes. Attributes from RedirectServlet are gone (unless you put them in the query string or in session).

3. Include — same screen, extra stamp

Wrong UPI PIN. The app does not open a new website. It prints “Wrong PIN” on the same payment form. That is include: same request, extra HTML pasted in, then the original servlet can continue.

What you will see

Run Forward: URL still /forward; Target can print the message. Run Redirect: URL becomes /target; that message is missing unless you passed it in the query. That pair of observations is the whole proof.

Easy mistake

Writing HTML and then calling forward (response already committed). Or calling setAttribute and then sendRedirect and expecting Target to read the attribute — the bag was left in the first shop.

Real-life examples (short recap)

Forward — waiter to kitchen

You stay at the table. The kitchen prints the bill, but you are still Table 7. Another servlet writes the HTML; the URL is still the first servlet.

Redirect — food app → UPI / “please login again”

Zomato → PhonePe. Instagram “session expired” → login page. Address bar changes. Refresh will not re-POST the first form (PRG pattern).

Include — same payment screen

Wrong PIN: error line plus the original form on the same response. Capstone uses include on failure.

B) When to use forward vs redirect vs include

APIUSE WHENDO NOT USE WHEN
forwardShow a result page but keep the original URL; pass request attributes After a successful POST that must not be resubmitted on refresh (use redirect)
sendRedirectChange the address bar; PRG after POST; send the user to another URL You still need request attributes from the first servlet
includeReuse a header/footer or show the login form again after an error You want to stop this servlet and jump fully to another page (use forward)

D) Full syntax

// FORWARD — same request, URL stays /forward
request.setAttribute("message", "Hello from ForwardServlet");
RequestDispatcher rd = request.getRequestDispatcher("/target");
rd.forward(request, response);

// REDIRECT — new request, URL becomes /target
response.sendRedirect("target");

// INCLUDE — same request, then this servlet can write more
rd.include(request, response);
Code / LineSimple meaning
getRequestDispatcher("/target")Path inside this web app. Leading / is from the app root.
forward(request, response)Do not write the HTML body before forward.
sendRedirect("target")Relative URL. Browser will request it next.
includeOutput of the included page is inserted into this response.

E) Functions — syntax, use and example

Each function below is the Java for the daily-life story above. Read the meaning, then the syntax, then the lab row.

Forward keeps the same request and the same URL. Redirect tells the browser to open a new URL.

1. Function: getRequestDispatcher

Simple meaning: Finds another servlet or HTML page inside this application.

Full syntax:

RequestDispatcher rd = request.getRequestDispatcher("target");
ItemSimple English
Parameterspath — servlet mapping or /file.html
ReturnsRequestDispatcher
When to use (USE)Next internal desk (forward) or paste another page (include).
Lab exampleForwardServlet uses "target" so TargetServlet runs.
Daily-life exampleKitchen is an internal path (“/kitchen”), not https://phonepe.com.
Common mistakeUsing a full http:// URL here — that is not an internal dispatcher.

2. Function: forward

Simple meaning: Hands this same request to the next servlet. Address bar does not change. setAttribute still works.

Full syntax:

rd.forward(request, response);
ItemSimple English
Parametersthe same request and response
Returnsvoid
When to use (USE)Login success → welcome page, URL still /forward or /CapstoneLogin.
Lab exampleExam form POST to /forward; bar still shows /forward; Target prints PASS.
Daily-life exampleWaiter walks the order slip to the kitchen. You still sit at Table 7.
Common mistakeWriting HTML, then calling forward — illegal state / committed response.

3. Function: include

Simple meaning: Pastes another servlet/page into this response, then your code continues.

Full syntax:

rd.include(request, response);
ItemSimple English
Parametersrequest, response
Returnsvoid
When to use (USE)Wrong password: show error line AND the login form again.
Lab exampleCapstoneLogin include /capstone.html on failure.
Daily-life exampleWrong UPI PIN: stamp “try again” on the same payment form.
Common mistakeThinking include changes the address bar — it does not.

4. Function: sendRedirect

Simple meaning: Sends HTTP 302. Browser opens a new request. Address bar changes. Request attributes are lost.

Full syntax:

response.sendRedirect("target");
ItemSimple English
ParametersA URL (relative or absolute)
Returnsvoid
When to use (USE)Payment gateway, “go to login”, Post-Redirect-Get after a POST.
Lab examplePOST to /redirect; bar becomes /target.
Daily-life exampleFood app sends you to PhonePe. Address bar becomes the UPI URL.
Common mistakeExpecting getAttribute after redirect — it is gone unless you put it in the query or session.

5. Function: setAttribute / getAttribute

Simple meaning: Carry a Java object on this request only. Survives forward. Does not survive redirect.

Full syntax:

request.setAttribute("message", "PASS");
String msg = (String) request.getAttribute("message");
ItemSimple English
Parametersname and value
Returnsvoid / Object
When to use (USE)Pass a flag from ForwardServlet to TargetServlet.
Lab exampleTarget prints FORWARD when message=PASS.
Daily-life exampleNotes on the restaurant slip survive the walk to the kitchen. They do not survive a trip to PhonePe.
Common mistakeUsing setAttribute then sendRedirect — Target will not see it.

F) Complete Java programs — every line explained

import java.io.IOException;
import jakarta.servlet.RequestDispatcher;        // Object that can forward or include
import jakarta.servlet.ServletException;
import jakarta.servlet.http.HttpServlet;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;

public class ForwardServlet extends HttpServlet {

    @Override
    protected void doPost(HttpServletRequest request, HttpServletResponse response)
            throws ServletException, IOException {
        go(request, response);
    }

    private void go(HttpServletRequest request, HttpServletResponse response)
            throws ServletException, IOException {
        String student = request.getParameter("student");           // Form / query name
        request.setAttribute("message", "Result for " + student + ": PASS"); // Same-request bag
        request.setAttribute("source", "ForwardServlet");           // Target can read this
        RequestDispatcher rd = request.getRequestDispatcher("/target"); // App-root path
        rd.forward(request, response);                              // URL stays /forward
    }
}
import java.io.IOException;
import jakarta.servlet.ServletException;
import jakarta.servlet.http.HttpServlet;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;

public class RedirectServlet extends HttpServlet {

    @Override
    protected void doPost(HttpServletRequest request, HttpServletResponse response)
            throws ServletException, IOException {
        go(request, response);
    }

    private void go(HttpServletRequest request, HttpServletResponse response) throws IOException {
        String student = request.getParameter("student");
        if (student == null) { student = "Rahul"; }
        response.sendRedirect("target?from=RedirectServlet&student="
                + java.net.URLEncoder.encode(student, "UTF-8")); // HTTP 302; new GET; URL changes
    }
}
import java.io.IOException;
import java.io.PrintWriter;
import jakarta.servlet.ServletException;
import jakarta.servlet.http.HttpServlet;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;

public class TargetServlet extends HttpServlet {

    // Redirect makes a new GET, so doGet is required.
    @Override
    protected void doGet(HttpServletRequest request, HttpServletResponse response)
            throws ServletException, IOException { show(request, response); }

    // Forward from the POST form keeps POST, so doPost is required.
    @Override
    protected void doPost(HttpServletRequest request, HttpServletResponse response)
            throws ServletException, IOException { show(request, response); }

    private void show(HttpServletRequest request, HttpServletResponse response) throws IOException {
        response.setContentType("text/html");
        PrintWriter out = response.getWriter();
        String msg = (String) request.getAttribute("message"); // Present after FORWARD only
        String from = request.getParameter("from");            // Present after REDIRECT query
        out.println("<h2>TargetServlet</h2>");
        if (msg != null) {
            out.println("<p>FORWARD: " + msg + " (URL still /forward)</p>");
        } else if (from != null) {
            out.println("<p>REDIRECT from " + from + " student="
                    + request.getParameter("student") + " (URL changed)</p>");
        } else {
            out.println("<p>Direct access</p>");
        }
        out.println("<p><a href='forward.html'>Back</a></p>");
    }
}
