9. Session Management - URL Rewriting

Theory Lab Setup Index
Verified for Apache Tomcat 11.0.24 (Jakarta EE 11 / Servlet 6.1) + JDK 17+
Every program uses jakarta.servlet.* only. See Lab Setup.

This page is theory only: meaning, real-life examples, diagrams, functions (syntax + use + example) and complete code. Copy the journal problem statement from the ICA Practicals tab or from the program Source page.

A) Concept in simple English

Some browsers (strict privacy / cookies blocked) will not store JSESSIONID. The session can still work if every next link carries the id: Url2;jsessionid=.... You must build that link with response.encodeURL, not with a raw href. This lab also passes s_id1 and s_id2 as ordinary query parameters (they are not the Tomcat session id).

If cookies are off, Tomcat cannot send JSESSIONID as a cookie. URL rewriting appends the session id to links: Url2;jsessionid=....

You must build links with response.encodeURL(...). If you write a raw href, the session can be lost.

This lab also passes two extra query ids: s_id1 and s_id2. Those are request parameters, not the Tomcat session id.

Picture it from daily life

One-line rule: If the luggage tag (cookie) will not stick, write the PNR on the next boarding pass (;jsessionid=...). Build that pass with encodeURL, not with a handwritten href.

The story (cookies blocked on a phone)

Safari / privacy mode may block cookies. Then Tomcat cannot keep JSESSIONID as a sticker. The hotel guest file (HttpSession) can still work if every next link carries the token in the URL:

Url2;jsessionid=ABC123?s_id1=054&s_id2=055

Think of a queue token printed on the slip you take to the next counter, because the sticker on your shirt fell off.

This lab also sends s_id1 and s_id2. Those are ordinary query parameters (extra notes on the slip). They are not the Tomcat session id. Viva: do not mix them.

If you write <a href="Url2"> by hand, you forgot to copy the token. The next counter treats you as a new stranger.

What you will see

Click the Url1 link. If cookies are off, the address bar shows ;jsessionid=. Url2 still prints the two query ids.

Easy mistake

Calling query parameters “the session id.” Session id is jsessionid. s_id1 is just data this program chose to send.

Real-life examples (short recap)

Phone with cookies blocked

Browser Settings → block cookies. A shopping cart that used only cookies would empty. encodeURL keeps the cart session in the link.

Older net-banking sites

You have seen long URLs with ;jsessionid=. That is URL rewriting for customers who disable cookies.

Cafe Wi-Fi login page

If the next button is a raw <a href="Url2"> without encodeURL, the rewritten id is lost and you look “logged out”.

E) Functions — syntax, use and example

Each function below is the Java for the daily-life story above. Read the meaning, then the syntax, then the lab row.

If the browser will not store cookies, put identity in the link itself.

1. Function: encodeURL

Simple meaning: If a session exists and cookies are off, Tomcat adds ;jsessionid=... to the URL. If cookies work, the URL stays clean.

Full syntax:

String url = response.encodeURL("Url2?s_id1=" + id1 + "&s_id2=" + id2);
ItemSimple English
ParametersThe next-page path plus your query string
ReturnsString (safe link to print in HTML)
When to use (USE)Always when you print a link to the next servlet in a session lab.
Lab exampleUrl1 prints a link to Url2 with both roll numbers in the query.
Common mistakeHard-coding the next URL without encodeURL when cookies are disabled — session is lost.

2. Function: getParameter (from the rewritten URL)

Simple meaning: Reads the ids that travelled in the query string (and still works if jsessionid is in the path).

Full syntax:

String a = request.getParameter("s_id1");
ItemSimple English
Parameterss_id1 / s_id2
ReturnsString
When to use (USE)Url2 page shows both numbers.
Lab exampleAddress bar shows Url2?s_id1=054&s_id2=055
Common mistakeUsing POST for this lab — the point is to see ids in the URL.

F) Complete Java programs — every line explained

import java.io.*;
import jakarta.servlet.*;
import jakarta.servlet.http.*;

public class Url1 extends HttpServlet {

    public void doGet(HttpServletRequest request, HttpServletResponse response)
            throws ServletException, IOException {
        String id1 = request.getParameter("s_id1");     // Extra data, NOT jsessionid
        String id2 = request.getParameter("s_id2");
        if (id1 == null) { id1 = "054"; }               // Default roll-like token
        if (id2 == null) { id2 = "055"; }
        String url = response.encodeURL("Url2?s_id1=" + id1 + "&s_id2=" + id2);
        // encodeURL may insert ;jsessionid=... before ? if cookies are off
        response.setContentType("text/html");
        PrintWriter out = response.getWriter();
        out.println("<h2>Url1</h2>");
        out.println("<p><a href='" + url + "'>next page</a></p>"); // Must use encoded URL
        out.println("<p><a href='url.html'>Back</a></p>");
    }
}
public class Url2 extends HttpServlet {
    public void doGet(HttpServletRequest request, HttpServletResponse response)
            throws ServletException, IOException {
        response.setContentType("text/html");
        PrintWriter out = response.getWriter();
        out.println("<h2>Url2</h2>");
        out.println("<p>s_id1=" + request.getParameter("s_id1") + "</p>"); // Query value
        out.println("<p>s_id2=" + request.getParameter("s_id2") + "</p>");
        out.println("<p><a href='url.html'>Back</a></p>");
    }
}
