3. GET vs POST Request and Differences

Theory Lab Setup Index
Verified for Apache Tomcat 11.0.24 (Jakarta EE 11 / Servlet 6.1) + JDK 21+
Every program uses jakarta.servlet.* only. See Lab Setup.

This page is theory only: meaning, real-life examples, diagrams, functions (syntax + use + example) and complete code. Copy the journal problem statement from the ICA Practicals tab or from the program Source page.

A) Concept in simple English

You want to (a) search YouTube / Google by a name and (b) submit a Gmail password. Both jobs send a name. If you use GET for both, the name (and any secret) appears in the URL, history and server logs. If you use POST for a simple search, a friend cannot bookmark the result. The lab uses class GetPostDiffServlet at URL /getpostdiff; the address bar is the proof.

GET and POST are the two methods you use every day with HTML forms.

GET means read/fetch. Form fields are added to the URL as a query string: /getpostdiff?name=Rahul. Easy to bookmark. Visible in history and logs.

POST means submit/send. Form fields go in the request body. The address bar usually stays /getpostdiff without the name. Better for login and large data.

In the servlet, both still use request.getParameter("name"). The difference is where the data travelled, not the Java read API.

Picture it from daily life

One-line rule: GET writes the data on the token (address bar). POST puts the data in a closed envelope (request body). Java still opens both with getParameter.

The story (Google search vs Gmail login)

Two everyday jobs:

  1. Search by name — You want to WhatsApp a Google / IRCTC result link. The friend should open the same page. That link must contain the name. That is GET: /getpostdiff?name=Rahul. Bookmark works. History shows the name. Fine for a search, never for a password.
  2. Login / send a secret — You type a Gmail or Instagram password. If it appeared in the URL, anyone behind you, the browser history, and the server log would all see it. That is POST. The address bar stays /getpostdiff. Refresh may warn “resubmit the form.”

Both forms can have a box named name. The servlet reads request.getParameter("name") in both doGet and doPost. The difference is the road the data travelled, not the Java read method.

What you will see

Run GET with name Rahul — URL changes. Run POST with the same name — URL does not show the name. The result page prints the method so you can prove which road was used.

Easy mistake

Saying “POST cannot use getParameter.” It can. Or putting a password on a GET form because “it is only a lab.” The address bar will still leak it.

Real-life examples (short recap)

GET — Google / YouTube search

You search “Rahul”. You copy the URL and send it to a friend. They open the same result. Bookmark works. That is GET.

POST — Gmail / Instagram login

You type a password. If it appeared as /login?pwd=servlet, anyone behind you, or any proxy log, would see it. Login therefore uses POST. Refresh after POST may warn “resubmit form” — that is also part of the observation.

WhatsApp a link vs pay button

A search link can be shared (GET). A “Pay now” button must not be a shareable URL (POST).

    throws ServletException, IOException {
  show(request, response);

private void show(HttpServletRequest request, HttpServletResponse response) throws IOException {
  String method = request.getMethod();
  String name = request.getParameter("name");
  response.setContentType("text/html");
  PrintWriter out = response.getWriter();
  out.println("Current method: " + method);
  out.println("name parameter: " + name);
}

F) Complete Java program — every line explained

import java.io.IOException;                      // Writer can throw IOException
import java.io.PrintWriter;                      // HTML character writer
import jakarta.servlet.ServletException;         // Required on doGet / doPost
import jakarta.servlet.http.HttpServlet;         // HTTP servlet base class
import jakarta.servlet.http.HttpServletRequest;  // Parameters + getMethod()
import jakarta.servlet.http.HttpServletResponse; // Content type + writer

public class GetPostDiffServlet extends HttpServlet {  // One class, two HTTP methods

    @Override
    protected void doGet(HttpServletRequest request, HttpServletResponse response)
            throws ServletException, IOException {          // Browser used method=get
        String q = request.getParameter("q");               // Query string field (search box)
        show(request, response, "GET search q=" + q
                + " URL=" + request.getQueryString());      // Query string is visible proof
    }

    @Override
    protected void doPost(HttpServletRequest request, HttpServletResponse response)
            throws ServletException, IOException {          // Browser used method=post
        String name = request.getParameter("name");         // Body field — not in the URL
        String message = request.getParameter("message");   // Second body field
        show(request, response, "POST saved name=" + name + " message=" + message
                + " query=" + request.getQueryString());    // Query is usually null on POST
    }

    private void show(HttpServletRequest request, HttpServletResponse response, String msg)
            throws IOException {
        response.setContentType("text/html");               // HTML response
        PrintWriter out = response.getWriter();             // Open writer
        out.println("<h2>request.getMethod() = " + request.getMethod() + "</h2>"); // GET or POST
        out.println("<p>" + msg + "</p>");
        out.println("<p><a href='getpostdiff.html'>Back</a></p>");
    }
}
