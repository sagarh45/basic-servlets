1. Servlets Introduction, Need and Working

Theory Diagram Syntax Lab Setup
Verified for Apache Tomcat 11.0.24 (Jakarta EE 11 / Servlet 6.1) + JDK 21+
Every program uses jakarta.servlet.* only. See Lab Setup.

This page is theory only: meaning, real-life examples, diagrams, functions (syntax + use + example) and complete code. Copy the journal problem statement from the ICA Practicals tab or from the program Source page.

A) Concept in simple English

A printed cinema timetable is the same for everyone. A static HTML file can show it. A ticket search is different: you type a movie name and must see your seat. A file typed once cannot do that. The site needs a server-side Java program (a servlet) to read the form and choose the matching record.

A Servlet is a Java class that runs on the server inside a servlet container (Apache Tomcat 11). The browser never runs servlet code. The browser only sends an HTTP request and displays the HTML that the servlet writes.

Introduction: Servlet = server-side Java used to build dynamic web pages.
Need: Static HTML cannot change for each user. A servlet can use if/else, loops, forms, and session data.
Working: Browser request → Tomcat 11 → web.xml mapping → doGet/doPost → HTML response.

In this lab every HTTP servlet extends jakarta.servlet.http.HttpServlet.

Servlet container (Tomcat) jobs you do not write: open port 8080, read HTTP, create threads, find the servlet from the URL, call the matching doXxx method, send the bytes back to the browser.

Your jobs: write the Java class, map it in web.xml, compile to WEB-INF/classes.

Picture it from daily life

One-line rule: A servlet is a Java worker inside Tomcat. Your phone browser never runs that Java. The worker reads the request and writes an HTML page back.

The story (printed menu vs food-delivery app)

Imagine two things.

  1. A paper restaurant menu is the same for every guest. A static HTML file can show it. No worker is needed.
  2. A Swiggy / Zomato order status is different. You type order 101. Your friend types order 205. Each must see a different dish and ETA. A file typed once cannot do that. A worker must look up the order. That worker is the servlet.

Chrome does not know the restaurant database. Chrome only knows how to send “please show order 101” and how to paint HTML. Tomcat (the kitchen building) receives the message, finds the right worker from web.xml, and the worker prints the page.

What you will see

Open /hello. The heading “Welcome to Servlets” was not typed in a .html file. Java printed it. The address bar still shows a normal URL. That is dynamic output.

Easy mistake

Thinking “the browser runs the servlet.” It does not. If Tomcat is stopped, the page cannot be generated. Static notes still open; servlets do not.

Real-life examples (short recap)

1) Printed bus timetable vs live PNR status

A PDF “Bus 12 leaves at 6 pm” is static. IRCTC PNR search is dynamic: you type a PNR and must see your train. Only a servlet can read the PNR and choose the matching record.

2) Gmail / Instagram login

After POST of user name and password, the next page must say “Welcome java”. That if/else lives in a servlet. One HTML file cannot do it.

3) Amazon order receipt

Each order needs a different receipt number. The browser never calculates that. Tomcat runs the servlet; the servlet writes HTML with that order’s data.

Rule to remember: If the page must change for each user, each form, or each login — use a Servlet. If the page never changes (a poster image, static notes) — plain HTML is enough.

Learning objectives

  • Explain servlet, servlet container, request and response in one paragraph.
  • Map a URL in web.xml to a Java class.

D) Full syntax (short form)

import java.io.IOException;
import java.io.PrintWriter;
import jakarta.servlet.ServletException;
import jakarta.servlet.http.HttpServlet;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;

public class MyServlet extends HttpServlet {
  @Override
  protected void doGet(HttpServletRequest request, HttpServletResponse response)
      throws ServletException, IOException {
    response.setContentType("text/html");
    PrintWriter out = response.getWriter();
    out.println("<h1>Hello from Servlet</h1>");
  }
}
Code / LineSimple meaning
extends HttpServletMakes this class an HTTP servlet that Tomcat can call.
doGet(request, response)Runs when the browser uses GET (link, address bar, form method=get).
setContentType("text/html")Tell the browser the body is HTML. Call this BEFORE writing.
getWriter()Gives PrintWriter to write the HTML page.
out.println(...)One line of HTML sent to the browser.

E) Functions — syntax, use and example

Each function below is the Java for the daily-life story above. Read the meaning, then the syntax, then the lab row.

Read each card in simple English. Tomcat calls these methods. You write the body.

1. Function: doGet

Simple meaning: Runs when the browser uses GET (link, address bar, or form method=get). You write the HTML page here.

Full syntax:

protected void doGet(HttpServletRequest request, HttpServletResponse response)
        throws ServletException, IOException
ItemSimple English
Parametersrequest = incoming URL and fields. response = object used to send HTML back.
Returnsvoid (nothing). The page is the output.
When to use (USE)First page, search, open a URL. HelloServlet uses only doGet.
Lab exampleStudent opens /hello. Tomcat calls doGet. Page shows “Welcome to Servlets”.
Common mistakeWrong spelling of doGet, or missing throws — Tomcat will not call your method.

2. Function: response.setContentType

Simple meaning: Tells the browser: the body is an HTML page, not a download or plain text.

Full syntax:

response.setContentType("text/html");
ItemSimple English
Parameterstype — use "text/html" in this lab.
Returnsvoid
When to use (USE)Always, before you write HTML.
Lab exampleHelloServlet calls it first, then getWriter().
Common mistakeWriting HTML first, then setContentType — the browser may show garbage.

3. Function: response.getWriter

Simple meaning: Gives a printer that sends characters (HTML) to the browser.

Full syntax:

PrintWriter out = response.getWriter();
ItemSimple English
Parametersnone
ReturnsPrintWriter
When to use (USE)Every servlet that prints a page.
Lab exampleout.println("<h1>Welcome to Servlets</h1>");
Common mistakeDo not also call getOutputStream() on the same response.

4. Function: out.println

Simple meaning: Sends one line of HTML to the browser.

Full syntax:

out.println("<p>This page is generated by Java.</p>");
ItemSimple English
ParametersA String (the HTML text).
Returnsvoid
When to use (USE)Build the visible page line by line.
Lab exampleHelloServlet prints heading, paragraph, and a Back link.
Common mistakeForgetting <html> is OK for a short lab page; forgetting setContentType is not.

F) Complete Java program — every line explained

File name: HelloServlet.java (must match the public class name). Place the compiled .class in WEB-INF/classes.

import java.io.IOException;                 // Checked exception for I/O (writer, network)
import java.io.PrintWriter;                 // Class used to print characters (HTML) to the client
import jakarta.servlet.ServletException;    // Exception type required on servlet method signatures
import jakarta.servlet.http.HttpServlet;    // Parent class that understands GET, POST, ...
import jakarta.servlet.http.HttpServletRequest;   // Object that holds URL, parameters, headers
import jakarta.servlet.http.HttpServletResponse;  // Object used to set status, type, and body

public class HelloServlet extends HttpServlet {   // Public class Tomcat will load by name

    private static final long serialVersionUID = 1L;  // Version id for Serializable (HttpServlet is serializable)

    @Override                                         // Compiler checks that we really override doGet
    protected void doGet(HttpServletRequest request,  // Incoming request from the browser
                         HttpServletResponse response) // Outgoing response we will fill
            throws ServletException, IOException {    // Required throws clause of HttpServlet.doGet

        response.setContentType("text/html");         // Header: body is HTML, not plain text or JSON

        PrintWriter out = response.getWriter();       // Get the character stream to the browser
        out.println("<!DOCTYPE html>");               // Start a legal HTML5 document
        out.println("<html>");                        // Root HTML element
        out.println("<head><title>Hello Servlet</title></head>"); // Browser tab title
        out.println("<body>");                        // Visible page starts
        out.println("<h1>Welcome to Servlets</h1>");  // Main heading generated by Java
        out.println("<p>This page is generated by HelloServlet using doGet().</p>"); // Proof it is dynamic
        out.println("<p><a href='index.html'>Back to Index</a></p>"); // Link back to the lab home
        out.println("</body>");                       // End visible page
        out.println("</html>");                       // End HTML document

        System.out.println("[HelloServlet] doGet() executed."); // Message on Tomcat console, not in browser
    }                                                 // End of doGet
}                                                     // End of class

G) Complete web.xml for this program

Copy this whole file into WEB-INF/web.xml. Only the tags this program needs.

<?xml version="1.0" encoding="UTF-8"?>
<web-app xmlns="https://jakarta.ee/xml/ns/jakartaee"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="https://jakarta.ee/xml/ns/jakartaee
         https://jakarta.ee/xml/ns/jakartaee/web-app_6_1.xsd"
         version="6.1">
    <servlet>
        <servlet-name>HelloServlet</servlet-name>
        <servlet-class>HelloServlet</servlet-class>
    </servlet>
    <servlet-mapping>
        <servlet-name>HelloServlet</servlet-name>
        <url-pattern>/hello</url-pattern>
    </servlet-mapping>
</web-app>
XML lineMeaning
version="6.1"Matches Tomcat 11. Do not write web-app 2.5 / javax.
<servlet-name>A label. It is not the URL and not the .java file name (though we keep them similar).
<servlet-class>Must match the public class. Default package in this lab (no package. prefix).
<url-pattern>/hello</url-pattern>The path the student types after /basic-servlets.
Two blocks with the same servlet-nameFirst block = who. Second block = which URL. Both names must be identical.

H) Expected output and viva

Output: a heading “Welcome to Servlets” and a short paragraph. The address bar shows /hello. Nothing is typed as a static .html file for that heading — Java printed it.

Viva (with model answers):

Q. Who executes servlet code?
A. Apache Tomcat 11 on the server. The browser only displays HTML.

Q. Why not put Java in the browser?
A. The browser does not have the servlet container, web.xml, or server data (student records, sessions).

Q. What happens if servlet-name in mapping does not match servlet-name in servlet?
A. Tomcat cannot find the class for that URL. You get 404 or a deployment error.

Q. Why jakarta.servlet and not javax.servlet?
A. Tomcat 11 implements Jakarta EE 11. javax.servlet is the old Java EE name (Tomcat 9 and below).
