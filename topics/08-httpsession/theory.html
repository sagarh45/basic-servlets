8. Session Management - HttpSession

Theory Lab Setup Index
Verified for Apache Tomcat 11.0.24 (Jakarta EE 11 / Servlet 6.1) + JDK 21+
Every program uses jakarta.servlet.* only. See Lab Setup.

This page is theory only: meaning, real-life examples, diagrams, functions (syntax + use + example) and complete code. Copy the journal problem statement from the ICA Practicals tab or from the program Source page.

A) Concept in simple English

Gmail / Instagram remembers who you are on every inner page until you log out or the session times out. That memory is on the server (HttpSession). The browser only keeps a session id (usually cookie JSESSIONID). Login for this lab: user java, password servlet. Password must travel in POST, never in the GET URL.

HttpSession is memory on the server for one user (one browser session). Tomcat tracks it with a cookie named JSESSIONID. Only that id travels to the browser, never the data itself.

Login stores username. Welcome reads it. Logout calls invalidate().

Picture it from daily life

One-line rule: HttpSession is the hotel’s guest file at the reception cupboard (server memory). The browser only carries a token number (JSESSIONID). Logout throws the whole file away (invalidate).

The story (Gmail / IRCTC login)

You log in to Gmail as java / servlet (POST, because the password must not sit in the URL). After that, Inbox, Sent and Settings all know who you are. Gmail is not printing your password on every page. The office opened a file labelled with a secret token and put username = java inside it.

  1. Login — getSession(true) means “open a file if you do not have one.” Then setAttribute("username", login).
  2. Welcome — getSession(false) means “do not open a new empty file if nobody logged in.” Read getAttribute("username"). If null, send them to login.
  3. Logout — invalidate(). The cupboard file is destroyed. The next person on the same cafe laptop must not still be “java”.

Cookie vs session (do not mix in the journal): cookie = sticker on the bag (“remember display name”). session = file at reception (“this person is logged in”). The session id cookie is only the token to find the file, not the data inside it.

What you will see

After login, Welcome prints the user. After logout, Welcome has no username. Restart Tomcat and lab sessions die (they lived in server memory).

Easy mistake

Calling getSession(true) on Welcome. That creates a blank session for a stranger and looks “logged in” with empty data. Welcome must use false.

Real-life examples (short recap)

Gmail / Instagram

After login, Inbox and Settings all know you. That is one HttpSession with attributes, not a note stuck on the laptop.

Cafe Wi-Fi shared laptop

If you only close the tab without logout, the next person on the same browser may still be “you” until timeout. That is why logout must call invalidate().

Cookie vs session

Cookie = small value in the browser (“remember my display name”). Session = map in Tomcat (“you are logged in as java”). Do not mix the two in the journal.

B) When to use HttpSession

Use HttpSession whenUse Cookie instead when
Login identity, cart, marks — data must stay on the serverSmall non-secret preference the browser can keep
You must remove all user data at logout (invalidate)You only need a remember-name cookie
Many values for one user across pagesOne tiny name=value is enough

getSession(true) on login (create if missing). getSession(false) on welcome (do not create an empty session). invalidate() on logout.

D) Full syntax

import jakarta.servlet.http.HttpSession;

// LOGIN
HttpSession session = request.getSession(true);
session.setAttribute("username", login);
response.sendRedirect("NotesSessionWelcome");

// WELCOME
HttpSession session = request.getSession(false);
if (session == null) { /* not logged in */ }
String user = (String) session.getAttribute("username");

// LOGOUT
HttpSession session = request.getSession(false);
if (session != null) {
  session.invalidate();
}

E) Functions — syntax, use and example

Each function below is the Java for the daily-life story above. Read the meaning, then the syntax, then the lab row.

HttpSession is a map on the server. The browser only keeps a session id (usually a cookie named JSESSIONID).

1. Function: getSession(true) / getSession()

Simple meaning: Get the existing session, or create one. Use after a successful login.

Full syntax:

HttpSession session = request.getSession(true);
ItemSimple English
Parameterstrue = create if missing (default). false = do not create.
ReturnsHttpSession (or null if false and none exists)
When to use (USE)Login success: store the user name.
Lab examplesession.setAttribute("username", "java");
Common mistakeCalling getSession(true) on the welcome page when you only wanted to check login — that can create an empty session.

2. Function: getSession(false)

Simple meaning: Return the session if it exists. Return null if the student is not logged in. Do not create a new one.

Full syntax:

HttpSession session = request.getSession(false);
ItemSimple English
Parametersfalse
ReturnsHttpSession or null
When to use (USE)Welcome and Logout: check before showing data.
Lab exampleIf session == null, sendRedirect to the login page.
Common mistakeUsing getSession() without false on Welcome — a guest would get a new empty session.

3. Function: setAttribute

Simple meaning: Put a value in server memory, keyed by a name.

Full syntax:

session.setAttribute("username", login);
ItemSimple English
Parametersname, value (any Object)
Returnsvoid
When to use (USE)After password check succeeds.
Lab exampleusername = java in this lab.
Common mistakeStoring the password in the session. Store only the login id.

4. Function: getAttribute

Simple meaning: Read the value back on the next request (same session id).

Full syntax:

String user = (String) session.getAttribute("username");
ItemSimple English
Parametersname used in setAttribute
ReturnsObject — cast to String. null if missing.
When to use (USE)Welcome page greeting.
Lab exampleWelcome java after forward from login.
Common mistakeForgetting the cast, or using a different key spelling.

5. Function: invalidate

Simple meaning: Destroy the session. Next getSession(false) is null. Student is logged out.

Full syntax:

session.invalidate();
ItemSimple English
Parametersnone
Returnsvoid
When to use (USE)Logout button.
Lab exampleNotesSessionLogout then redirect to the login form.
Common mistakeOnly deleting a cookie and forgetting invalidate — the session would still exist on the server.

F) Complete Java programs — every line explained

import java.io.IOException;
import java.io.PrintWriter;
import jakarta.servlet.ServletException;
import jakarta.servlet.http.HttpServlet;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;
import jakarta.servlet.http.HttpSession;          // Server-side session API

public class NotesSessionLogin extends HttpServlet {

    @Override
    protected void doPost(HttpServletRequest request, HttpServletResponse response)
            throws ServletException, IOException {            // Login form MUST be POST
        String login = request.getParameter("login");         // User box
        String pwd = request.getParameter("pwd");             // Password box (body, not URL)
        if (login != null && pwd != null
                && login.equals("java") && pwd.equals("servlet")) {
            HttpSession session = request.getSession(true);   // Create session if missing
            session.setAttribute("username", login);          // Store identity on the SERVER
            response.sendRedirect("NotesSessionWelcome");     // New GET so refresh is safe
            return;
        }
        response.setContentType("text/html");
        PrintWriter out = response.getWriter();
        out.println("<p>Wrong login. Use java / servlet.</p>");
        out.println("<p><a href='session_notes_login.html'>Back</a></p>");
    }
}
public class NotesSessionWelcome extends HttpServlet {
    public void doGet(HttpServletRequest request, HttpServletResponse response)
            throws ServletException, IOException {
        response.setContentType("text/html");
        PrintWriter out = response.getWriter();
        HttpSession session = request.getSession(false);      // Do NOT create an empty session
        if (session == null || session.getAttribute("username") == null) {
            response.sendRedirect("session_notes_login.html"); // Not logged in
            return;
        }
        String user = (String) session.getAttribute("username"); // Cast Object → String
        out.println("<h1>Welcome " + user + "</h1>");
        out.println("<p><a href='NotesSessionLogout'>Logout</a></p>");
    }
}
public class NotesSessionLogout extends HttpServlet {
    public void doGet(HttpServletRequest request, HttpServletResponse response)
            throws ServletException, IOException {
        HttpSession session = request.getSession(false);      // Existing session or null
        if (session != null) {
            session.invalidate();                             // Destroy ALL attributes + id
        }
        response.sendRedirect("session_notes_login.html");    // Back to login form
    }
}
